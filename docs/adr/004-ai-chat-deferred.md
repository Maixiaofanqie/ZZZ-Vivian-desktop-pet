# ADR-004 · AI 聊天暂缓

- **状态**：已接受
- **日期**：2026-10-24
- **决策者**：项目维护者

## 背景

原计划接入 DeepSeek/OpenAI 兼容模型，提供自由聊天。进入该阶段前确认了两个实际顾虑：
1. **无法与 Claude Code 内部会话联动**：Claude Code 没有对外暴露当前会话内容的公开接口；本机 `~/.claude/projects/*.jsonl` 虽存在，但读取对话内容超出项目既定的隐私边界（ADR-003 明确只读元数据）。
2. **成本**：独立 API Key 会产生持续费用，日常陪伴场景下性价比不确定。

Claude Code 联动已能只读项目元数据，并可通过 `vscode://anthropic.claude-code/open?session=<id>` 打开指定会话——这解决了「跳到工作现场」的问题，但不提供对话内容。

## 选项

| 选项                                       | 优点                                    | 缺点                                               |
| ------------------------------------------ | --------------------------------------- | -------------------------------------------------- |
| A 暂缓 AI 聊天，先完成元数据联动与信息模块 | 零额外成本；不碰对话内容；v1.0 范围更稳 | v1.0 没有自由聊天                                  |
| B 本地模型（Ollama / llama.cpp）           | 免费、隐私好                            | 质量与速度依赖硬件；打包与模型分发复杂             |
| C Claude Code CLI 后端（`claude -p`）      | 复用现有登录，不单独买 Key              | 每次起进程、延迟高；可能消耗订阅额度；不是内部会话 |
| D BYOK + 严格限额                          | 质量可控                                | 仍有费用；需要 Key 管理与预算控制                  |

## 决策

**AI 聊天暂缓，不放进 v1.0。** 先完成 Claude Code 元数据联动与信息模块，把陪伴体验做完整。后续作为可选的「AI 后端」重新评估，候选为本地模型、Claude Code CLI 或 BYOK 限额方案；届时另写决策记录。

会话跳转只使用 session id 与官方 URI，**不读取对话内容、prompt、代码**。

## 后果

- 正面：v1.0 无 API 费用与密钥管理负担；隐私边界清晰；元数据联动与信息模块能独立提供价值。
- 负面：没有自由文本聊天；用户只能使用本地台词、记忆、作息与 Claude Code 现场感知。
- 后续：重新评估时补写模型、预算、Key 存储与断网降级决策。
