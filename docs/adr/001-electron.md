# ADR-001 · 技术栈选择 Electron + TypeScript

- **状态**：已接受
- **日期**：2026-10-21
- **决策者**：项目维护者

## 背景

需要开发一个 Windows 11 长期驻留的桌面宠物：透明置顶窗口、拖拽与物理、静态形象与轻量动效、对话气泡、设置面板、功能模块、可打包分发。

## 选项

| 选项                      | 优点                                                                 | 缺点                                                   |
| ------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------ |
| **Electron + TypeScript** | 透明窗口/托盘/自启/打包生态成熟；React UI 开发效率高；无需额外工具链 | 内存约 150–300MB；安装包约 100MB                       |
| Python + PySide6          | 体积较小；Python 生态                                                | 透明窗口与点击穿透处理繁琐；动画与 UI 开发慢；打包坑多 |
| Tauri                     | 包体最小、性能好                                                     | 需要 Rust 工具链；引入额外学习与构建成本               |

## 决策

采用 **Electron + TypeScript + electron-vite**。UI 使用 React；最终角色渲染为**静态透明图 + Canvas 2D + CSS transform**，不使用 PixiJS、Live2D 或序列帧。

## 后果

- 正面：开发迭代快；透明窗口、托盘、单实例、自启、NSIS 打包均有成熟方案。
- 负面：常驻内存与安装包体积较大；需严格控制性能预算（空闲 CPU < 2%、内存 < 250MB）。
- 后续：若未来极端在意内存，可重新评估 Tauri，但不影响 v1.0。
