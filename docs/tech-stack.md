# 技术选型

## 技术栈总览

| 层面          | 选择                             | 说明                                    |
| ------------- | -------------------------------- | --------------------------------------- |
| 桌面运行时    | Electron 45                      | 透明窗口、托盘、自启、NSIS 打包生态成熟 |
| 语言          | TypeScript 7（strict）           | 主进程 / preload / 渲染层全 TS          |
| 构建          | electron-vite 6 + Vite 8         | 一套配置构建三层，开发热更新            |
| UI            | React 19                         | 设置页、功能面板、气泡                  |
| 角色渲染      | Canvas 2D 静态图 + CSS transform | 无 PixiJS / Live2D / 序列帧             |
| 状态管理      | React 本地状态 + IPC 事件        | 不引入全局状态库                        |
| 校验          | zod 4                            | IPC 入参与持久化数据校验                |
| 格式化 / lint | Biome 2                          | 单工具、速度快                          |
| 单元测试      | Vitest 5                         | 状态机、规则、纯函数                    |
| 打包          | electron-builder 26 + NSIS       | 按用户安装、可选目录、卸载清理          |
| Node          | 24.x                             | `.nvmrc` 与 `engines` 均有约束          |

## 版本策略

- 源码构建使用 Node.js 24.x；Electron 内置 Node 版本与系统 Node 无关，运行时不依赖系统 Node。
- 依赖版本以 `package-lock.json` 锁定；升级依赖必须单独提交并跑完整 `npm run verify` 与 `npm run build`。
- 不引入原生模块（node-gyp），避免 ABI 与打包问题；确需引入须新增 ADR。
- Electron 大版本由维护者手动升级；Dependabot 只提小版本与补丁。

## 依赖准入原则

新增一个依赖前必须回答：
1. 标准库 / 现有依赖能否解决？能则不新增。
2. 是否活跃维护、是否有已知高危漏洞？
3. 打包体积与内存代价是否可接受？
4. 是否能在渲染进程无特权的前提下使用？

## 性能预算

| 指标                 | 目标                          |
| -------------------- | ----------------------------- |
| 空闲 CPU（宠物待机） | < 2%（单核占用）              |
| 常驻内存（全部进程） | < 250MB                       |
| 冷启动到宠物出现     | < 3 秒                        |
| 拖拽跟随             | ≥ 55 FPS 视觉流畅             |
| 安装包体积           | < 150MB                       |
| 连续运行             | 24 小时无崩溃、无持续内存增长 |

超出预算视为缺陷，需要记录并给出缓解方案。

## 安全约束（强制）

- `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`。
- preload 保持 CJS，只通过 `contextBridge` 暴露白名单 API。
- 渲染进程不得访问文件系统、网络、密钥、Node API。
- 所有 IPC 入参用 zod 校验；每个 handler 校验发送方窗口身份。
- 密钥使用 Electron `safeStorage`（Windows DPAPI）加密存储，仅主进程可读；当前版本不需要用户提供 API Key。
- 禁止将密钥写入源码、日志或提交历史。
- 外部链接一律 `shell.openExternal`，禁止在应用内打开远程页面。
- 渲染页面设置 CSP，禁止 `unsafe-eval`。

## Windows 平台已知限制

| 现象                         | 原因           | 应对                                                  |
| ---------------------------- | -------------- | ----------------------------------------------------- |
| 独占全屏游戏上方无法显示     | 系统独占模式   | 建议用户使用无边框全屏；这是系统行为                  |
| UAC 安全桌面、锁屏不可覆盖   | 系统安全机制   | 不尝试绕过                                            |
| 未签名安装包触发 SmartScreen | 无代码签名证书 | 文档说明；必要时再评估签名                            |
| 混合 DPI 跨屏位置跳变        | 窗口坐标与缩放 | 统一使用 DIP；监听 `display-metrics-changed` 重新夹紧 |

## 技术风险

| 风险                           | 等级 | 缓解                                                                   |
| ------------------------------ | ---- | ---------------------------------------------------------------------- |
| 透明窗口 / 逐像素穿透不稳定    | 高   | 以合成画布的 alpha 面罩驱动 `setIgnoreMouseEvents`；透明区域不拦截点击 |
| 多窗口 + 透明 + GPU 在核显闪烁 | 中   | 限制窗口数量；提供关闭待机微动效的开关                                 |
| 内存占用偏高                   | 中   | 性能预算 + 浸泡采样；不在渲染层常驻大图                                |
| Claude Code 元数据格式变化     | 中   | 扫描失败时回退目录名/短 id，不崩溃；只读一层目录                       |
